function SimFeat_LegalCounts($player) {
  $player = intval($player);
  $legal = [];
  $hand = &GetHand($player);
  SimFeat_MergeCounts($legal, SimFeat_Counts(SimFeat_ZoneIDs($hand, HandPieces())));
  SimFeat_MergeCounts($legal, SimFeat_Counts(SimV1_DeckCards($player)));
  SimFeat_MergeCounts($legal, SimFeat_Counts(SimFeat_ZoneIDs(GetArsenal($player), ArsenalPieces())));

----------------------------------------------------------------
Why this matters (the R17 mechanism): every other zone in the
featurization is read through the getter VIEWS (GetHand, GetDeck,
...), which the engine settles as it plays; the deck slice alone
comes from the lagging STORE. Between Choose's featurization and
the checkpoint sync (DoGamestateUpdate: store := view), a settling
pitch therefore changes the deck slice - and only that slice -
which is exactly the feat_pre != feat_post shape localized in the
fc8faef package (ARS, seed 7). R17 makes the teacher's root
evaluation use the bridge's own (pre-sync) featurization, which
is the input the deployed bridge player actually decides on.
