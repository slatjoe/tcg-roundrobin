THE MECHANISM (rl/eval.py) - what ties the seat

File: /home/joe/tcg/tcg-sim/rl/eval.py

eval.py does not ping the server for its seat (the ping endpoint is
new in fc8faef). The tie is made at spawn time, and the attribution
is read back from the server's own per-game records:

  rl/eval.py:153
    learner_seat = {"a": "1", "b": "2"}.get(args.learner_deck)

  rl/eval.py:165-166 (env is the environment the server process is
  spawned with at rl/eval.py:169-170)
    if learner_seat is not None:
        env["TCG_LEARNER_SEAT"] = learner_seat

  rl/eval.py:187-188 (the PHP child's environment, --policy search)
    if learner_seat is not None:
        php_env["TCG_LEARNER_SEAT"] = learner_seat

So for the search_server lineage, the server's LEARNER_SEAT
constant and the PHP TCG_LEARNER_SEAT both come from the same
--learner-deck flag value, set by the same code, on the two
processes eval.py itself spawns.

For seat attribution after the run, eval.py reads the seat back
from the server's own records - it does not trust its flag:

  rl/eval.py:232-235
    # Seat attribution: prefer games_meta.jsonl (one line per game
    # at game start: {"game", "learner_seat", "opp", "ts"}), fall
    # back to scanning traj lines (each learner decision carries
    # game + learner_seat).

  rl/eval.py:239-242
    if ("game" in r and "learner_seat" in r
            and str(r["game"]) not in seats):
        seats[str(r["game"])] = int(r["learner_seat"])

  rl/eval.py:246-253 reads traj/games_meta.jsonl line by line into
  that map; rl/eval.py:273-278 then counts a win only where the
  game's winner equals the RECORDED seat:
    for g, s in seats.items():
        if winners.get(g) == s:
            wins += 1

For the rollout_server lineage (--policy net), the server assigns
each game's learner seat itself, stores it in that game's record,
routes the game's decisions by the stored record, and writes the
same record to games_meta.jsonl - a seat swap cannot be produced
by a launcher flag, because there is no second seat variable.
